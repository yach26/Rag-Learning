# RAGForge Architecture Report (Phase 3)

This document summarizes the architecture of the fully upgraded RAGForge system, built incrementally across three phases. The system has evolved from a basic LangChain-style prototype into a highly modular, production-ready Advanced RAG pipeline entirely implemented from scratch.

## 🏗️ System Architecture

RAGForge is built on the following core components:

### 1. Ingestion & Document Processing (`src/ingest.py`)
- **Incremental Ingestion:** Uses MD5 hashing of file contents (`hash_store.py`) to skip re-ingesting unchanged files, saving time and API costs.
- **Semantic Chunking:** Breaks documents down using SentenceTransformers to ensure meaningful paragraph boundaries.
- **Multimodal Support:** Integrates Tesseract OCR to read text from image files.
- **Graph Building:** An offline script (`src/graph_builder.py`) extracts Named Entities from chunks and maps them to chunk IDs, creating a lightweight entity knowledge graph without needing a heavy database like Neo4j.

### 2. The Vector Database Layer
- **Dense Store (`src/vector_store.py`):** Uses ChromaDB for vector similarity search (cosine distance).
- **Sparse Store (`src/bm25_store.py`):** An in-memory BM25 index rebuilt on startup to enable exact keyword matching, compensating for vector search's weakness with specific vocabulary/IDs.

### 3. Query Transformation (`src/query/`)
Before hitting the database, the user's query can undergo several transformations:
- **Conversation Awareness (`rewrite.py`):** Uses chat history to resolve coreferences (e.g., turning "what about the second one?" into "what about the second framework mentioned?").
- **Spellcheck (`rewrite.py`):** Fixes typos that would otherwise misalign the query vector in embedding space.
- **Query Expansion (`expansion.py`):** Generates synonyms and related terms to cast a wider net for keyword matching.
- **Multi-Query (`multi_query.py`):** Generates completely different phrasings of the same question to overcome vocabulary mismatch.
- **HyDE (`hyde.py`):** Hallucinates a "perfect" answer and embeds it to bridge the semantic gap between questions and declarative answers.

### 4. Advanced Retrieval Pipeline (`src/retriever.py`)
The retriever dispatches to multiple strategies based on user selection:
- **Hybrid Search:** Runs both Dense (Chroma) and Sparse (BM25) searches simultaneously, merging their results using **Reciprocal Rank Fusion (RRF)**.
- **Graph-Augmented Dense:** Extracts entities from the query, instantly looks up exact chunks from the offline entity graph, and merges them with semantic search results to guarantee 100% recall on specific entities.
- **CrossEncoder Reranking (`src/reranker.py`):** All massive candidate pools generated by Multi-Query, HyDE, or Graph-Augmentation are passed through a lightweight CrossEncoder (e.g., `ms-marco-MiniLM-L-6-v2`) to mathematically re-score the chunks against the original query, ensuring only the most highly relevant chunks make it into the final context window.

### 5. Generation & Guardrails
- **Self-Correcting RAG (`src/generator.py`):** Instead of immediately streaming an answer, the system can draft an answer and evaluate it against the context using an `EVALUATOR_PROMPT`. If it detects hallucination, it falls back safely.
- **Input/Output Guardrails (`src/guardrails.py`):** Fast local regex intercepts prompt injections (e.g., "ignore previous instructions") and filters toxic output before display.
- **Response Caching (`src/cache.py`):** Exact semantic matches are cached to disk, allowing instant responses for repeated questions.

## 🔬 Experiment Harness
RAGForge includes an `experiments/` directory designed to benchmark every single technique in isolation.
- `reranking.py`
- `query_transformation.py`
- `multi_query.py`
- `hyde.py`
- `self_correction.py`
- `graph_rag.py`
- `long_context.py`
- `evaluator.py` (LLM-as-a-judge for Context Relevance & Answer Faithfulness)

## 🚀 Conclusion
RAGForge demonstrates that a production RAG system is not just a vector database and an LLM. It is a highly orchestrated pipeline of query transformations, hybrid search strategies, reranking, and safety guardrails — all designed to maximize relevance and eliminate hallucination.
